# 微信模块增强方案（基于新架构）

## 新旧架构对比

### 旧版本架构
```
WechatWorkChannel（企业微信 API）
         ↓
BotIntegration（核心逻辑：命令、会话、消息处理）
         ↓
IFlowController（tmux 管理）
```
**特点**：功能集中，耦合度高

### 新版本架构
```
WeChatModule（企业微信消息收发）
         ↕
MessageBus（消息路由、绑定）
         ↕
IFlowModule（iflow 管理、监控）
```
**特点**：模块独立，职责单一，通过消息总线通信

## 功能归属分析

### 应该继承到 WeChatModule 的功能

| 功能 | 说明 | 原因 | 状态 |
|------|------|------|------|
| 消息确认机制 | 收到企业微信消息后立即发送确认 | 属于企业微信层面的用户体验 | ✅ 已实现 |
| 消息去重机制 | 使用 MsgId 避免重复处理 | 属于企业微信消息处理的基础功能 | ✅ 已实现 |
| 详细日志 | 收发消息的详细记录 | 属于企业微信模块的调试功能 | ✅ 已实现 |

**WeChatModule 职责**：纯粹的企业微信消息收发，不处理业务逻辑

### 应该继承到 IFlowModule 的功能

| 功能 | 说明 | 原因 |
|------|------|------|
| 会话管理 | 创建、查询、删除会话 | 属于 iflow 会话管理 |
| 消息清理 | 移除 iflow UI 元素 | 属于 iflow 输出处理 |
| 回复提取增强 | 从 tmux 提取回复 | 属于 iflow 监控功能 |

**IFlowModule 职责**：iflow 的完整管理，包括会话和输出

### 需要重新设计的功能

| 功能 | 新架构下的实现方式 | 原因 |
|------|------------------|------|
| 命令系统 | 消息总线层或独立 CommandHandler | 命令需要跨模块协调 |
| 连续对话 | 通过消息总线绑定实现 | 旧版本在 BotIntegration，新版本应解耦 |

**实现位置**：`src/modules/wechat/channel.py` - `_process_callback_async()`

### 2. 消息去重机制

**实现位置**：`src/modules/wechat/channel.py` - `_is_duplicate_message()`

**设计思路**：
- 使用 MsgId 进行去重
- 维护一个消息 ID 缓存（TTL: 1小时）
- 定期清理过期缓存

**实现方式**：
```python
async def _is_duplicate_message(self, msg_id: str) -> bool:
    """检查是否为重复消息"""
    current_time = time.time()
    
    # 清理过期缓存
    self._processed_msg_ids = {
        k: v for k, v in self._processed_msg_ids.items()
        if current_time - v < 3600
    }
    
    if msg_id in self._processed_msg_ids:
        return True
    
    self._processed_msg_ids[msg_id] = current_time
    return False
```

### 2. 消息清理

**实现位置**：`src/modules/iflow/monitor.py`

**设计思路**：
- 从 iflow 输出中移除 UI 元素
- 识别多种分隔符格式
- 提取纯净的消息内容

**实现方式**：
```python
class IFlowMonitor:
    def _clean_message_content(self, content: str) -> str:
        """清理消息内容，移除 iflow UI 元素"""
        if not content:
            return content
        
        # 分隔符列表
        separators = [
            '---', '══', '────────', '────────────────',
            '════════════════', '══════════════════════════',
        ]
        
        # 找到第一个分隔符
        for sep in separators:
            pos = content.find(sep)
            if pos != -1:
                return content[:pos].strip()
        
        return content.strip()
```

### 3. 回复提取增强

**实现位置**：`src/modules/iflow/monitor.py`

**设计思路**：
- 支持 ✦ 和 ✻ 标记消息识别
- 过滤思考消息（✻ 标记）
- 实时监控并发送新消息

**实现方式**：
```python
class IFlowMonitor:
    def _extract_messages(self, lines: List[str]) -> List[Dict]:
        """从 tmux 输出中提取消息"""
        messages = []
        current_marker = None
        current_content = []
        
        for line in lines:
            if '✦' in line or '✻' in line:
                # 保存上一条消息
                if current_marker and current_content:
                    content = '\n'.join(current_content).strip()
                    # 清理内容
                    cleaned_content = self._clean_message_content(content)
                    if cleaned_content:
                        messages.append({
                            'marker': current_marker,
                            'content': cleaned_content,
                            'type': 'thinking' if '✻' in line else 'response'
                        })
                
                # 开始新消息
                current_marker = line.replace('✦', '').replace('✻', '').strip()
                current_content = []
            else:
                current_content.append(line)
        
        # 保存最后一条消息
        if current_marker and current_content:
            content = '\n'.join(current_content).strip()
            cleaned_content = self._clean_message_content(content)
            if cleaned_content:
                messages.append({
                    'marker': current_marker,
                    'content': cleaned_content,
                    'type': 'thinking' if '✻' in line else 'response'
                })
        
        return messages
```

## 命令系统设计

### 方案一：在 IFlowModule 中实现

**优点**：
- 实现简单
- 命令与 iflow 紧密相关

**缺点**：
- IFlowModule 职责增加
- 未来扩展其他模块的命令困难

### 方案二：创建独立的 CommandHandler 模块

**优点**：
- 职责清晰
- 易于扩展
- 支持多模块命令

**缺点**：
- 需要额外的模块

**推荐方案二**：创建 `src/modules/command_handler/`

**实现方式**：
```python
# src/modules/command_handler/module.py
class CommandHandlerModule(BaseModule):
    """命令处理模块"""
    
    def __init__(self, module_id: str = "command_handler"):
        super().__init__(module_id)
        self.commands = {}
        self._register_builtin_commands()
    
    def _register_builtin_commands(self):
        """注册内置命令"""
        self.register_command("/help", self._cmd_help)
        self.register_command("/status", self._cmd_status)
        self.register_command("/new", self._cmd_new_session)
        self.register_command("/sessions", self._cmd_list_sessions)
    
    def register_command(self, name: str, handler: Callable):
        """注册命令"""
        self.commands[name] = handler
    
    async def _on_receive(self, message: Message) -> None:
        """接收消息"""
        content = message.content.text.strip()
        
        # 检查是否为命令
        if content.startswith("/"):
            parts = content.split(maxsplit=1)
            cmd_name = parts[0]
            cmd_args = parts[1] if len(parts) > 1 else ""
            
            if cmd_name in self.commands:
                # 执行命令
                await self.commands[cmd_name](message, cmd_args)
            else:
                # 未知命令
                await self._send_unknown_command(message)
        else:
            # 不是命令，转发给 iflow
            await self.send_to_bus(message)
```

## 多实例支持

### 实例区分方式

每个 WeChatModule 实例通过以下参数区分：

| 参数 | 说明 | 用途 |
|------|------|------|
| `module_id` | 模块唯一标识符 | MessageBus 注册和消息路由 |
| `corp_id` | 企业 ID | 标识不同的企业微信 |
| `agent_id` | 应用 AgentId | 标识同一企业下的不同应用 |
| `callback_port` | 回调监听端口 | 区分不同实例的 HTTP 服务 |

### 多实例示例

```python
from src.core.bus import MessageBus
from src.modules.wechat.module import WeChatModule

bus = MessageBus()

# 实例1: 企业A的应用1
wechat1 = WeChatModule(
    module_id="wechat_bot1",
    corp_id="corp_a",
    agent_id="10001",
    secret="secret_a",
    callback_port=8787
)

# 实例2: 企业A的应用2（同一企业不同应用）
wechat2 = WeChatModule(
    module_id="wechat_bot2",
    corp_id="corp_a",
    agent_id="10002",
    secret="secret_b",
    callback_port=8788
)

# 实例3: 企业B的应用
wechat3 = WeChatModule(
    module_id="wechat_bot3",
    corp_id="corp_b",
    agent_id="10001",
    secret="secret_c",
    callback_port=8789
)

# 注册所有实例
bus.register_module(wechat1)
bus.register_module(wechat2)
bus.register_module(wechat3)

# 设置绑定（每个微信实例绑定到对应的 iflow 实例）
bus.bind("wechat_bot1", "iflow_bot1")
bus.bind("wechat_bot2", "iflow_bot2")
bus.bind("wechat_bot3", "iflow_bot3")
```

### 端口隔离

不同实例必须监听不同端口，HTTP 回调地址示例：

```
实例1: http://your-server:8787/wechat/callback
实例2: http://your-server:8788/wechat/callback
实例3: http://your-server:8789/wechat/callback
```

企业微信后台配置时，每个应用使用对应的回调地址。
