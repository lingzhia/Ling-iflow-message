# 重构设计方案

本目录记录了 Ling-iflow 项目的重构设计方案。

## 背景

当前模块架构存在以下问题：
- 职责不清：模块耦合严重
- 扩展困难：添加新功能需要修改核心代码
- 维护复杂：代码职责重叠

## 重构目标

实现基于**发布-订阅模式**和**消息总线**的松耦合架构。

## 核心改进

### 四大核心组件

1. **消息渠道** - 企业微信、模拟器等多种消息渠道
2. **消息分发模块（消息总线）** - 模块间消息路由和分发
3. **iflow 消息模块** - iflow CLI 的完整管理
4. **模块管理器** - 模块生命周期管理和状态监控

### 通用组件

1. **消息转换器** - 统一的消息格式转换
2. **通知管理器** - 模块事件通知管理

### 架构优势

- **解耦清晰** - 模块间通过消息总线通信
- **扩展性强** - 添加新功能无需修改现有代码
- **灵活度高** - 支持多对多绑定和动态绑定
- **易于维护** - 模块独立开发测试，故障隔离
- **统一管理** - 模块管理器统一管理模块生命周期和状态

- 所有渠道可复用 MessageConverter
- 所有渠道可复用 NotificationManager
- 新增渠道工作量减少约 50%
