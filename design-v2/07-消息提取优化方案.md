# 消息提取优化方案

## 问题分析

### 当前问题

1. **消息内容缺失** - 只提取标记行，丢失了后续行的内容
2. **消息重复发送** - 检测机制不准确导致重复
3. **生成中消失不稳定** - 有时会短暂消失又重新出现，导致误判结束

### iflow 输出格式

```
✦ 回复标题
  缩进的内容行1
  缩进的内容行2

✻ 思考中...
  思考内容

⠦ 生成中 6m 37s ... (按esc取消)
```

### 标记说明

- **✦ (回复标记)** - iflow 的实际回复内容，默认对外发送
- **✻ (思考标记)** - iflow 的思考过程，内部记录但不对外发送
- **⠦ 生成中** - 状态指示器，表示 iflow 正在生成回复

### 核心原则

1. **完整记录** - IFlowMonitor 必须记录 iflow 中的全部消息，无论前面是什么标记（✦ 或 ✻）
2. **选择性发送** - 对外回复的消息默认情况下只发送 ✦ 标记的消息，✻ 标记的消息不发送
3. **状态检测** - 状态检测只关注"生成中"关键词及其持续时间，不依赖前面的符号 ⠦

## 旧版本方案分析

### 核心策略：延迟提取

**核心思想**：检测到新标记时，提取并发送**倒数第二个**标记消息（它是完整的，不会再变化）。

### 工作流程

```
时间线：
T1: 检测到标记1 [✦ 回复1] → 记录（候选）
T2: 检测到标记2 [✦ 回复2] → 发送标记1（倒数第二，完整），记录标记2
T3: 检测到标记3 [✦ 回复3] → 发送标记2（倒数第二，完整），记录标记3
...
Tn: 生成中消失（稳定2秒）→ 发送最后一个标记（此时也是完整的）
```

### 关键特性

1. **倒数第二原则** - 每次检测到新标记时，发送上一个标记（倒数第二）
2. **完整保证** - 倒数第二的标记已经完整，不会再变化
3. **生成中也会发送** - 生成中时的新标记也会被记录并发送
4. **稳定结束** - "生成中"消失并稳定2秒后，才判断回复结束

### 实现逻辑

```python
# 旧版本伪代码
last_messages = []  # 记录所有标记消息
stable_start_time = None  # 稳定开始时间

while monitoring:
    current_messages = extract_all_messages(output)
    is_generating = detect_generating(output)
    
    # 检测新标记
    if len(current_messages) > len(last_messages):
        # 有新标记
        if len(last_messages) >= 1:
            # 发送倒数第二的（即 last_messages 的最后一个）
            send_message(last_messages[-1])
        
        # 更新记录
        last_messages = current_messages
        stable_start_time = None  # 重置稳定计时器
    
    # 检测生成中消失（需要稳定2秒）
    elif not is_generating and len(last_messages) > 0:
        if stable_start_time is None:
            # 第一次检测到消失，开始计时
            stable_start_time = now()
        elif (now() - stable_start_time) >= 2:
            # 稳定2秒，确认结束
            send_message(last_messages[-1])
            last_messages = []
            stable_start_time = None
    else:
        # 生成中重新出现，重置计时器
        stable_start_time = None
```

## 新方案设计

### 方案概述

采用**延迟提取策略 + 稳定检测机制**，确保发送的消息是完整的，并且准确判断回复结束。

**核心改进**：
1. **记录候选消息** - 每次检测到新标记，记录它
2. **发送上一个** - 检测到新标记时，发送上一个候选（倒数第二，保证完整）
3. **稳定结束** - 生成中消失并稳定2秒后，才判断回复结束
4. **重新出现处理** - 生成中重新出现时，重置稳定计时器

### 实现方案

#### 2. 重构 `_extract_messages` - 完整内容提取

```python
def _extract_messages(self, output: str) -> List[Dict]:
    """从 tmux 输出中提取消息
    
    提取策略：
    - 检测标记行（✦ 或 ✻）
    - 收集标记行及所有后续缩进的内容
    - 跳过 UI 行（生成中、分隔符等）
    
    Args:
        output: tmux 输出
        
    Returns:
        消息列表
    """
    messages = []
    lines = output.split('\n')
    
    for i, line in enumerate(lines):
        # 检查标记行
        if '✦' in line or '✻' in line:
            # 提取标记内容（去掉标记符号）
            marker_type = '✦' if '✦' in line else '✻'
            marker_content = line.replace('✦', '').replace('✻', '').strip()
            
            if not marker_content:
                continue
            
            # 收集后续行（消息延续）
            content_lines = [marker_content]
            
            # 遍历后续行，收集缩进的内容
            for j in range(i + 1, len(lines)):
                next_line = lines[j]
                
                # 如果遇到新的标记行或分隔符，停止
                if '✦' in next_line or '✻' in next_line or next_line.startswith('---') or next_line.startswith('═') or next_line.startswith('─'):
                    break
                
                # 跳过"生成中"等 UI 行
                if '生成中' in next_line and '按' in next_line:
                    continue
                
                # 如果行以缩进开头，认为是消息延续
                if next_line.startswith('  ') or next_line.startswith('\t'):
                    content_lines.append(next_line.strip())
                else:
                    # 非缩进行，停止
                    break
            
            # 合并内容
            full_content = '\n'.join(content_lines)
            
            messages.append({
                'content': full_content,
                'marker_type': marker_type,
                'marker_only': marker_content  # 用于哈希计算
            })
    
    return messages
```

#### 3. 重构 `_check` - 延迟提取逻辑 + 稳定检测

```python
async def _check(self) -> None:
    """检查新消息和状态（延迟提取策略 + 稳定检测）"""
    self.stats["check_count"] += 1
    
    try:
        # 捕获 tmux 输出
        output = await self.controller.capture_output(lines=1000)
        
        if not output:
            return
        
        # 提取所有消息
        current_messages = self._extract_messages(output)
        
        # 检测生成状态
        is_generating = self._detect_generating(output)
        
        # 检测新标记
        if len(current_messages) > len(self._candidate_messages):
            # 有新标记
            new_message_count = len(current_messages) - len(self._candidate_messages)
            
            logger.debug(f"[IFlowMonitor] 检测到 {new_message_count} 个新标记，当前总数: {len(current_messages)}")
            
            # 如果有上一个候选，发送它（倒数第二，保证完整）
            if len(self._candidate_messages) > 0:
                message_to_send = self._candidate_messages[-1]
                await self._send_message(message_to_send)
            
            # 更新候选缓存
            self._candidate_messages = current_messages
            
            # 重置稳定计时器（有新标记，说明还在生成）
            self._stable_start_time = None
        
        # 检测生成中消失（需要稳定2秒）
        elif not is_generating and len(self._candidate_messages) > 0:
            if self._stable_start_time is None:
                # 第一次检测到消失，开始计时
                self._stable_start_time = datetime.now()
                logger.debug(f"[IFlowMonitor] 检测到生成中消失，开始稳定计时...")
            else:
                # 检查稳定时间
                stable_time = (datetime.now() - self._stable_start_time).total_seconds()
                
                if stable_time >= self._stable_duration:
                    # 稳定2秒，确认结束
                    logger.info(f"[IFlowMonitor] 生成中稳定消失（{stable_time:.1f}s），发送最后一条消息")
                    
                    # 发送最后一个候选
                    message_to_send = self._candidate_messages[-1]
                    await self._send_message(message_to_send)
                    
                    # 清空候选缓存
                    self._candidate_messages = []
                    self._stable_start_time = None
                else:
                    logger.debug(f"[IFlowMonitor] 等待稳定... ({stable_time:.1f}s / {self._stable_duration}s)")
        
        # 生成中重新出现，重置计时器
        elif is_generating:
            if self._stable_start_time is not None:
                logger.debug(f"[IFlowMonitor] 生成中重新出现，重置稳定计时器")
                self._stable_start_time = None
        
        # 检测状态变化
        await self._check_state(output)
        
    except Exception as e:
        logger.error(f"[IFlowMonitor] Error checking messages: {e}", exc_info=True)

async def _send_message(self, message_data: Dict) -> None:
    """发送消息（带去重）"""
    marker_content = message_data.get('marker_only', '')
    marker_type = message_data.get('marker_type', '')
    
    # 计算哈希
    msg_hash = hashlib.md5(f"{marker_type}:{marker_content}".encode()).hexdigest()
    
    # 检查是否已发送
    if msg_hash in self._processed_hashes:
        logger.debug(f"[IFlowMonitor] 消息已发送，跳过: {marker_content[:50]}")
        return
    
    # 添加到已发送集合
    self._processed_hashes.add(msg_hash)
    
    # 限制缓存大小
    if len(self._processed_hashes) > 1000:
        self._processed_hashes = set(list(self._processed_hashes)[-500:])
    
    # 创建出站消息
    msg_type = MessageType.REPLY if marker_type == '✦' else MessageType.OTHER
    
    message = OutboundMessage(
        type=msg_type,
        content=message_data['content'],
        receiver="",
        scope="reply_only",
        timestamp=datetime.now(),
        metadata={'marker_type': marker_type}
    )
    
    # 通知订阅者
    await self._notify_subscribers(message)
    self.stats["messages_extracted"] += 1
    
    logger.info(f"[IFlowMonitor] 发送消息: {marker_content[:50]}")
```

#### 4. 重构 `_check_state` - 状态检测

```python
async def _check_state(self, output: str) -> None:
    """检测 iflow 状态"""
    is_generating = self._detect_generating(output)
    
    old_state = self._state
    
    if is_generating and self._state == IFlowState.IDLE:
        # 状态变更：空闲 -> 生成中
        self._state = IFlowState.GENERATING
        self._generating_start_time = datetime.now()
        self.stats["state_changes"] += 1
        logger.info(f"[IFlowMonitor] State changed: {old_state.value} -> {self._state.value}")
        
        if self._on_state_change:
            await self._call_callback(self._on_state_change, old_state, self._state)
    
    elif not is_generating and self._state == IFlowState.GENERATING:
        # 状态变更：生成中 -> 空闲（仅当稳定后才真正变更状态）
        if self._stable_start_time is not None:
            stable_time = (datetime.now() - self._stable_start_time).total_seconds()
            if stable_time >= self._stable_duration:
                # 稳定后，真正变更状态
                duration = self.generating_duration
                self._state = IFlowState.IDLE
                self._generating_start_time = None
                self.stats["state_changes"] += 1
                logger.info(f"[IFlowMonitor] State changed: {old_state.value} -> {self._state.value}, duration={duration}s")
                
                if self._on_state_change:
                    await self._call_callback(self._on_state_change, old_state, self._state, duration)
```

## 总结

新方案的核心改进：
1. **延迟提取** - 检测到新标记时，发送上一个标记（倒数第二，保证完整）
2. **候选缓存** - 记录所有标记消息，作为后续发送的候选
3. **稳定结束** - 生成中消失并稳定2秒后，才判断回复结束

6. **哈希去重** - 基于标记行内容，避免重复发送

这个方案确保发送的消息都是完整的，并且准确判断回复结束，同时解决了消息内容缺失和重复发送的问题。

## 最新方案：两阶段检测 + 字符串定位

### 方案概述

采用**两阶段检测策略**和**字符串定位机制**，进一步提升性能和准确性。

**核心改进**：
1. **两阶段检测**：未在生成中时只提取 50 行，减少不必要的处理
2. **内容清理**：去掉 TUI 界面和无关内容
3. **精确提取**：区分 iflow 收到的消息和带标记的消息
4. **字符串定位**：用标记行字符串定位，简化去重逻辑
5. **延迟发送**：最后统一发送，避免发送不完整的中间版本

### 监测流程（两阶段）

```

└─────────────────────────────────────────────────────────┘
    ↓
每 0.5 秒提取 tmux 中的 50 行
    ↓
检测是否有"生成中"
    ↓
┌─────────────────────────────────────┐
│ 没有"生成中" → 不处理，继续检测    │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 有"生成中" → 切换到阶段2            │

└─────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ 阶段2：完整记录（检测到"生成中"）                          │
└─────────────────────────────────────────────────────────┘
    ↓
每 0.5 秒提取 tmux 中的 1000 行
    ↓
内容处理
    ↓
┌─────────────────────────────────────┐
│ 1. 去掉 TUI 界面内容               │
│ 2. 去掉最新一条发送消息前的内容     │
└─────────────────────────────────────┘
    ↓
消息提取
    ↓
┌─────────────────────────────────────┐
│ 1. 提取 iflow 收到的消息           │

└─────────────────────────────────────┘
    ↓

    ↓

└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 后续扫描：                          │
│ - 找到上次记录的最后标记行          │

    ↓

    ↓
┌─────────────────────────────────────┐

└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ 不存在 → 记录最后一条，结束         │
│ - 记录最后一条标记消息              │
│ - 统一发送所有记录的消息            │

└─────────────────────────────────────┘
```
