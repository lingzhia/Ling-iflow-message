## 一、设计目标

在 Ling-iflow 项目中新增飞书渠道支持，实现与企业微信渠道一致的业务逻辑，同时保持架构统一性和代码复用性。

### 1.1 核心原则

- **架构一致**: 复用现有消息总线架构，与企业微信渠道保持一致
- **业务统一**: 消息内容、命令系统、通知机制与企业微信渠道完全一致
- **参考最佳实践**: 连接方式和功能范围参考 iflow-bot 项目实现
- **配置简化**: 使用独立配置节点，降低用户配置成本

## 二、架构决策

### 2.1 连接方式：WebSocket 长连接 ✅

**决策**: 采用 WebSocket 长连接方式（与 iflow-bot 一致）

| 对比项 | HTTP 回调 | WebSocket 长连接 |
|-------|----------|-----------------|
| 公网 IP | 需要 | **无需** |
| SDK | 原生 httpx | lark-oapi 官方 SDK |
| 代码量 | 400-500 行 | 1000+ 行 |
| 功能 | 基础文本 | 完整功能 |
| 流式输出 | ❌ | ✅ |
| 文件传输 | ❌ | ✅ |
| 打字动画 | ❌ | ✅ |

**优势**:
- 无需公网 IP，降低部署门槛
- 使用官方 SDK，稳定性和兼容性好
- 支持流式输出、文件传输等高级功能

```python
class FeishuChannel(BaseModule):
    """飞书消息通道
    
    继承 BaseModule，通过 WebSocket 长连接接收消息，
    使用 lark-oapi SDK 发送消息。
    """
    
    # 配置属性
    app_id: str                    # 飞书应用 ID
    app_secret: str                # 飞书应用密钥
    verification_token: str        # 验证 Token
    encrypt_key: str               # 加密密钥（可选）
    allow_from: List[str]          # 用户白名单
    notify_user_id: str            # 通知接收用户 ID
    
    # SDK 客户端
    _client: lark.Client           # SDK 客户端
    _ws_client: lark.ws.Client     # WebSocket 客户端
    _ws_thread: threading.Thread   # WebSocket 线程
    _ws_loop: asyncio.EventLoop    # WebSocket 事件循环
    
    # 缓存管理
    _processed_message_ids: OrderedDict  # 消息去重缓存
    _streaming_message_ids: Dict          # 流式消息 ID 缓存
    _streaming_last_content: Dict         # 流式消息最后内容
```

### 4.3 飞书开放平台配置步骤

#### 步骤 1: 创建应用

1. 登录 [飞书开放平台](https://open.feishu.cn/)
2. 进入「应用开发」→「企业自建应用」
3. 创建新应用，记录 App ID 和 App Secret

#### 步骤 2: 配置权限

在「权限管理」中添加以下权限：

**必选权限：**

| 权限名称 | 权限 Code | 用途 |
|---------|----------|------|
| 发送消息 | `im:message` | 向用户/群聊发送消息 |
| 获取用户信息 | `contact:contact:readonly` | 获取发送者信息 |
| 事件订阅 | `event:event:readonly` | 订阅消息接收事件 |
| 管理机器人 | `app:bot` | 启用机器人功能 |

**可选权限（高级功能）：**

| 权限名称 | 权限 Code | 用途 |
|---------|----------|------|
| 上传图片/文件 | `im:resource` | 发送图片/文件消息 |
| 下载图片/文件 | `im:file` | 接收图片/文件消息 |

#### 步骤 3: 配置事件订阅

1. 进入「事件订阅」功能
2. 配置验证 Token（自动生成，复制到配置文件）
3. 订阅以下事件：

**必选事件：**

| 事件名称 | 事件 Code | 用途 |
|---------|----------|------|
| 接收消息 v2.0 | `im.message.receive_v1` | 接收用户发送的消息 |

**可选事件：**

| 事件名称 | 事件 Code | 用途 |
|---------|----------|------|
| 消息已读 v2.0 | `im.message.message_read_v1` | 监听消息已读状态 |
| 添加表情回应 v2.0 | `im.message.reaction_created_v1` | 监听表情回应 |
| 删除表情回应 v2.0 | `im.message.reaction_deleted_v1` | 监听表情回应删除 |

4. 使用 WebSocket 方式，无需配置 URL
5. 发布应用

#### 步骤 4: 配置机器人

1. 启用「机器人」功能
2. 配置机器人名称和头像
3. 将机器人添加到需要使用的群聊

#### 步骤 5: 获取 notify_user_id

**notify_user_id（open_id）** 是飞书用户的唯一标识，用于接收启动/停止通知。

**获取方法：**

**方法 1：通过日志获取（推荐）**
1. 启动服务后，在飞书中向机器人发送一条消息
2. 查看日志：`tail -f logs/bot.log`
3. 日志中会显示发送者的 open_id（格式：`ou_xxxxx`）
4. 将 open_id 配置到 `notify_user_id` 字段

**方法 2：通过飞书开放平台获取**
1. 登录 [飞书开放平台](https://open.feishu.cn/)
2. 进入「应用开发」→ 选择你的应用
3. 进入「用户信息」或「权限管理」
4. 找到您的用户 ID（open_id 格式如：`ou_xxxxx`）

**方法 3：通过 API 获取**
```bash
curl -X GET "https://open.feishu.cn/open-apis/contact/v3/users/me" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

**注意**：未配置 notify_user_id 不影响消息功能，只是不会收到启动/停止通知。

#### 5.2.1 WebSocket 线程管理

```python
def _start_websocket_thread(self) -> None:
    """启动 WebSocket 线程"""
    def run_ws():
        while self._running:
            try:
                # 关键修复：替换模块级别的事件循环
                import lark_oapi.ws.client as ws_client_module
                new_loop = asyncio.new_event_loop()
                self._ws_loop = new_loop
                asyncio.set_event_loop(new_loop)
                ws_client_module.loop = new_loop
                
                self._ws_client.start()
            except Exception as e:
                logger.warning(f"WebSocket 异常：{e}")
            finally:
                # 清理事件循环
                if self._ws_loop:
                    self._ws_loop.close()
            
            if self._running:
                time.sleep(5)  # 重连等待
    
    self._ws_thread = threading.Thread(target=run_ws, daemon=True)
    self._ws_thread.start()
```

#### 5.2.2 消息接收与处理

```python
async def _handle_message_event(self, event: P2ImMessageReceiveV1) -> None:
    """处理消息接收事件"""
    message = event.event.message
    sender = event.event.sender
    
    message_id = message.message_id
    chat_id = message.chat_id
    sender_id = sender.sender_id.open_id
    msg_type = message.message_type
    content = message.content
    
    # 消息去重
    if await self._is_duplicate_message(message_id):
        return
    
    # 解析消息内容
    content = await self._parse_message_content(msg_type, content)
    
    # 确定回复目标
    chat_type = "group" if chat_id.startswith("oc_") else "private"
    reply_to = chat_id if chat_type == "group" else sender_id
    
    # 解析命令
    parsed = self.command_handler.parse_command(content)
    
    # 执行命令
    if parsed.get("is_command"):
        result = await self.command_handler.execute(parsed, reply_to)
        if result:
            await self.send_message(result, reply_to, "open_id")
            return
    
    # 发送到消息总线
    message_obj = self.converter.create_wechat_inbound_message({
        "content": content,
        "sender_id": sender_id,
        "chat_id": reply_to,
        "msg_type": msg_type
    }, self.module_id)
    
    await self.send_to_bus(message_obj)
```

#### 5.2.3 消息发送

```python
async def send_message(
    self,
    content: str,
    receive_id: str,
    receive_id_type: str,
    msg_type: str = "text"
) -> bool:
    """发送消息到飞书"""
    loop = asyncio.get_running_loop()
    
    if msg_type == "text":
        # 构建文本消息
        msg_content = json.dumps({"text": content}, ensure_ascii=False)
    elif msg_type == "interactive":
        # 构建交互卡片
        msg_content = self._build_interactive_card(content)
    else:
        msg_content = content
    
    # 同步发送
    message_id = await loop.run_in_executor(
        None,
        self._send_message_sync,
        receive_id_type,
        receive_id,
        msg_type,
        msg_content
    )
    
    return message_id is not None
```

## 八、已知限制

1. **流式输出**: 当前版本不支持流式输出（打字动画），消息在 iflow 完成生成后一次性发送
2. **Markdown 渲染**: 当前版本发送纯文本消息，不支持飞书卡片格式
3. **媒体上传**: 图片和文件上传功能已实现但未经充分测试

## 九、常见问题

### Q1: 消息发送失败

**可能原因：**
- 应用未启用
- 权限配置不完整
- 用户不在启用范围内

**解决方案：**
1. 检查应用是否已启用
2. 检查权限配置是否完整
3. 确认用户在启用范围内

### Q2: 收不到消息回调

**可能原因：**
- 事件订阅未配置
- 事件未发布
- Verification Token 配置错误

**解决方案：**
1. 检查事件订阅配置
2. 确认事件已发布
3. 重新验证 Verification Token

### Q3: WebSocket 连接失败

**可能原因：**
- App ID 或 App Secret 错误
- 网络连接问题
- 应用权限不足

**解决方案：**
1. 检查 App ID 和 App Secret 配置
2. 检查网络连接
3. 确认应用权限配置完整

### Q4: 权限申请失败

**解决方案：**
确保使用的是企业管理员账号，或联系管理员授权。

### Q5: 机器人无法发送消息

**解决方案：**
检查是否启用了「发送消息」权限，并确保应用已发布。
