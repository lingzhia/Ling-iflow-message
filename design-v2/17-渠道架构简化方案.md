# 渠道架构简化方案

## 一、方案概述

### 1.1 背景

当前的架构基于"组"的概念，配置复杂，包含多个层级：
- `groups` - 组定义
- `tmux_sessions` - iflow 会话配置
- `bots` - 企业微信渠道配置
- `simulator_channels` - 模拟器渠道配置

这种设计虽然灵活，但对于简单使用场景过于复杂。

### 1.2 简化目标

**核心原则：以渠道为中心，简化配置**

- 去掉 `groups` 配置，直接管理渠道
- 去掉 `tmux_sessions` 配置，使用命名规则
- 去掉 `workspace` 和 `model` 配置，使用默认值
- 命令行参数从 `-g` (group) 改为 `-c` (channel)
- iflow 与渠道绑定，使用命名规则

### 1.3 设计理念

**"一个渠道，一个 iflow"**

- 每个渠道对应一个 iflow 实例
- iflow 会话名：`渠道名+iflow`
- iflow 使用默认配置（当前目录、glm-4.7、--yolo）
- 简化配置，提升用户体验

**iflow 会话命名：**
- `wechat_bot1+iflow`
- `wechat_bot2+iflow`
- `simulator1+iflow`

**模块 ID 命名：**
- 渠道模块：`wechat_bot1`, `wechat_bot2`, `simulator1`
- iflow 模块：`iflow_wechat_bot1+iflow`, `iflow_wechat_bot2+iflow`, `iflow_simulator1+iflow`

## 三、命令行参数调整

### 3.1 参数变化

| 旧参数 | 新参数 | 说明 |
|--------|--------|------|
| `-g g1` | `-c bot1` | 启动/停止指定渠道 |
| `-g g2` | `-c bot2` | 启动/停止指定渠道 |
| `-g g_simulator` | `-c simulator1` | 启动/停止指定渠道 |
| `-g all` | `-a` | 启动/停止所有渠道 |
| `-g ls` | `-c ls` | 列出所有渠道 |

### 3.2 命令示例

**启动命令：**
```bash
# 启动默认渠道（wechat_bot1）
./manage.py start

# 启动所有渠道
./manage.py start -a

# 启动指定渠道
./manage.py start -c bot1
./manage.py start -c bot2
./manage.py start -c simulator1

# 查看可用渠道
./manage.py start -c ls
```

**停止命令：**
```bash
# 停止默认渠道（wechat_bot1）
./manage.py stop

# 停止所有渠道
./manage.py stop -a

# 停止指定渠道
./manage.py stop -c bot1
./manage.py stop -c bot2
```

**重启命令：**
```bash
# 重启默认渠道（wechat_bot1）
./manage.py restart

# 重启所有渠道
./manage.py restart -a

# 重启指定渠道
./manage.py restart -c bot1
./manage.py restart -c bot2
```

## 四、架构调整

### 4.1 模块创建逻辑

**旧逻辑（基于组）：**
1. 加载 groups 配置
2. 创建组1的模块
3. 注册其他组定义
4. 启动组1

**新逻辑（基于渠道）：**
1. 加载 bots 和 simulator_channels 配置
2. 确定要启动的渠道
3. 为每个渠道创建模块（WeChatChannel + IFlowModule）
4. 建立绑定关系
5. 启动渠道

### 4.2 模块结构

```
服务进程
├── 消息总线
├── 模块管理器
├── 渠道 bot1
│   ├── WeChatChannel (wechat_bot1)
│   ├── IFlowModule (iflow_wechat_bot1+iflow)
│   └── CommandHandler
├── 渠道 bot2
│   ├── WeChatChannel (wechat_bot2)
│   ├── IFlowModule (iflow_wechat_bot2+iflow)
│   └── CommandHandler
└── 渠道 simulator1
    ├── SimulatorChannel (simulator1)
    ├── IFlowModule (iflow_simulator1+iflow)
    └── CommandHandler
```

### 4.3 绑定关系

```
wechat_bot1 → MessageBus → iflow_wechat_bot1+iflow
wechat_bot2 → MessageBus → iflow_wechat_bot2+iflow
simulator1  → MessageBus → iflow_simulator1+iflow
```

## 九、总结

本方案通过简化配置文件和命令行参数，实现了：
1. **更简单的配置结构** - 去掉冗余配置
2. **更清晰的架构** - 以渠道为中心
3. **更直观的使用** - 1个渠道对应1个iflow
4. **更易的扩展** - 添加渠道更简单

这个简化方案在保持核心功能不变的前提下，大大降低了使用复杂度，提升了用户体验。

## 十、FAQ

### Q1: 如何升级到新版本？

**A:**
1. 备份当前配置文件
2. 运行配置迁移脚本（如果提供）
3. 更新命令脚本中的参数：`-g` → `-c`
4. 重启服务

### Q2: 如果我需要不同的工作目录怎么办？

**A:** 
在新方案中，工作目录默认使用当前目录。如需不同的工作目录：
```bash
cd /path/to/workspace
./manage.py start
```

### Q3: 如何添加新渠道？

**A:**
在 config.json 的 `bots` 或 `simulator_channels` 中添加配置，`tmux_session` 设置为 `渠道名+iflow`。

### Q4: 默认渠道是什么？

**A:**
默认渠道是配置文件中第一个启用的企业微信渠道（`bots` 中 `enabled: true` 的第一个）。

### Q5: 前台运行有什么用？

**A:**
使用 `-f` 参数前台运行，适合开发和调试场景，可以实时查看日志输出。
