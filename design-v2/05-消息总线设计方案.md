# 消息总线设计方案

## 概述

MessageBus（消息总线）是 Ling-iflow 项目的核心组件，负责模块间消息路由和分发。采用**发布-订阅模式**实现模块解耦。

---

## 核心理念

- **解耦**：模块间不直接依赖，通过消息总线通信
- **路由**：根据绑定关系自动路由消息
- **广播**：支持发布-订阅模式广播消息
- **统一管理**：集中管理模块生命周期

## 核心方法

### 模块管理

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `register_module(module)` | 注册模块 | bool |
| `unregister_module(module_id)` | 注销模块 | bool |
| `list_modules()` | 列出所有模块 | List[str] |

### 绑定管理

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `bind(from_module, to_module)` | 绑定两个模块 | bool |
| `unbind(from_module)` | 解绑模块 | bool |
| `get_binding(from_module)` | 获取绑定关系 | Optional[str] |
| `list_bindings()` | 列出所有绑定 | Dict[str, str] |

### 消息发送

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `send_to_module(message)` | 直接发送到指定模块 | bool |
| `route(message)` | 根据绑定关系路由 | bool |
| `publish(topic, message)` | 广播到主题 | bool |

### 订阅管理

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `subscribe(topic, callback)` | 订阅主题 | bool |
| `unsubscribe(topic, callback)` | 取消订阅 | bool |
| `list_topics()` | 列出所有主题 | Set[str] |

### 统计信息

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `get_stats()` | 获取统计信息 | Dict |
| `reset_stats()` | 重置统计信息 | None |

> **注意**：模块的启动/停止由 `LingIflowBot` 控制，MessageBus 只负责消息路由。

## 消息路由流程

### 点对点路由

```
消息到达 MessageBus.route()
        │
        ▼
检查 source_module 的绑定关系
        │
        ▼
bindings[source_module] → target_module_id
        │
        ▼
modules[target_module_id].receive(message)
```

**示例**：

```python
# 配置绑定
bus.bind("wechat_bot1", "iflow_bot1")

# 微信消息自动路由到 iflow
message = Message(
    from_module="wechat_bot1",
    content="你好"
)
await bus.route(message)  # 自动发送到 iflow_bot1
```

### 广播发布

```
消息到达 MessageBus.publish(topic)
        │
        ▼
获取主题的所有订阅者
        │
        ▼
并发调用所有订阅者回调
        │
        ▼
返回成功/失败统计
```

**示例**：

```python
# 订阅主题
async def on_reply(message):
    print(f"收到回复: {message.content}")

bus.subscribe("iflow_reply", on_reply)

# 发布消息
await bus.publish("iflow_reply", message)
```

## 典型使用场景

### 场景1：微信 ↔ iflow 双向绑定

```python
# 创建消息总线
bus = MessageBus()

# 创建模块
wechat = WeChatModule(module_id="wechat_bot1", ...)
iflow = IFlowModule(module_id="iflow_bot1", ...)

# 注册模块
bus.register_module(wechat)
bus.register_module(iflow)

# 设置双向绑定
bus.bind("wechat_bot1", "iflow_bot1")  # 微信 → iflow
bus.bind("iflow_bot1", "wechat_bot1")  # iflow → 微信

# 启动模块（由控制层管理）
await wechat.start()
await iflow.start()
```

### 场景2：多机器人配置

```python
# 机器人1：企业A

iflow1 = IFlowModule(module_id="iflow_bot1", tmux_session="iflow1")

# 机器人2：企业B
wechat2 = WeChatModule(module_id="wechat_bot2", corp_id="corp_b", ...)
iflow2 = IFlowModule(module_id="iflow_bot2", tmux_session="iflow2")

# 注册
bus.register_module(wechat1)
bus.register_module(iflow1)
bus.register_module(wechat2)
bus.register_module(iflow2)

# 绑定（各自独立）
bus.bind("wechat_bot1", "iflow_bot1")
bus.bind("iflow_bot1", "wechat_bot1")
bus.bind("wechat_bot2", "iflow_bot2")
bus.bind("iflow_bot2", "wechat_bot2")
```

### 场景3：命令处理器集成

```python
# 创建命令处理器
command = CommandHandler(module_id="command_handler")

# 注册
bus.register_module(command)

# 绑定命令处理器
bus.bind("wechat_bot1", "command_handler")  # 先路由到命令处理器
bus.bind("command_handler", "iflow_bot1")   # 非命令消息转发到 iflow
```

## 设计原则

### 1. 单一职责

- MessageBus 只负责消息路由和分发
- 不处理消息内容，不关心业务逻辑
- 模块职责独立，通过消息通信

### 2. 依赖倒置

- 模块不直接依赖其他模块
- 模块通过 MessageBus 通信
- 绑定关系运行时配置

### 3. 开闭原则

- 添加新模块无需修改 MessageBus
- 添加新绑定无需修改代码
- 扩展功能通过订阅机制

### 4. 异步优先

- 所有消息处理使用 async/await
- 并发处理提高性能
- 非阻塞操作

## 错误处理

### 错误类型

| 错误 | 处理方式 |
|------|---------|
| 模块不存在 | 记录日志，返回 False |
| 绑定不存在 | 记录日志，返回 False |
| 消息发送失败 | 记录异常，更新错误计数 |
| 订阅者处理失败 | 记录异常，继续处理其他订阅者 |

### 容错机制

```python
async def publish(self, topic: str, message: Message) -> bool:
    # 使用 return_exceptions 捕获所有异常
    results = await asyncio.gather(*tasks, return_exceptions=True)
    
    # 统计成功/失败
    success_count = sum(1 for r in results if not isinstance(r, Exception))
    
    # 记录错误但不影响其他订阅者
    if success_count < len(results):
        errors = [r for r in results if isinstance(r, Exception)]
        logger.error(f"{len(errors)} 个订阅者处理失败")
```

## 总结

MessageBus 作为 Ling-iflow 的核心组件，实现了：

- **模块解耦**：模块间通过消息通信，不直接依赖
- **灵活路由**：支持点对点路由和广播发布
- **生命周期管理**：集中管理模块启动/停止
- **易于扩展**：添加新模块无需修改核心代码

该设计满足当前项目需求，并为未来扩展预留了空间。
