# 命令系统设计

## 一、方案概述

### 1.1 背景

Ling-iflow 项目提供了统一的命令解析和执行机制，支持多种类型的命令（会话管理、状态查询、渠道管理等），易于扩展新的命令，支持命令透传（未知命令传递给 iflow 处理）。

### 1.2 核心目标

- 提供统一的命令解析和执行机制
- 支持多种类型的命令（会话管理、状态查询、渠道管理等）
- 易于扩展新的命令
- 支持命令透传（未知命令传递给 iflow 处理）
- 提供友好的帮助和错误提示

### 1.3 设计原则

**单一职责原则**
- CommandHandler 只负责命令解析和执行
- 各功能模块独立，职责清晰

**职责清晰**
- 命令处理独立于具体业务模块
- 每个命令有明确的职责和功能
- 命令结果格式统一

**易于扩展**
- 支持动态注册自定义命令
- 提供清晰的命令注册接口
- 支持命令别名和参数

**透传机制**
- 未知命令自动透传给 iflow 处理
- 保留 iflow 原生命令的完整性
- 避免命令冲突

## 二、系统架构

### 2.1 组件关系

```
用户渠道（企业微信 / 模拟器 / 其他渠道）
         │
         ▼
MessageBus（消息路由和分发）
         │
         ▼
CommandHandler（命令解析和执行）
  - 解析命令
  - 执行命令
  - 注册内置命令
         │
         ├──→ 已知命令 → 执行命令逻辑 → 返回结果
         │
         └──→ 未知命令 → 透传给 iflow → 返回结果
                   │
                   └──→ 路由回发送方
```

### 2.2 CommandHandler 核心组件

| 组件 | 位置 | 职责 |
|------|------|------|
| CommandHandler | `src/modules/command/handler.py` | 命令解析、命令执行、命令注册 |

**主要方法：**

| 方法 | 说明 |
|------|------|
| `__init__()` | 初始化命令处理器 |
| `parse_command()` | 解析用户消息，提取命令和参数 |
| `execute()` | 执行命令 |
| `_register_builtin_commands()` | 注册内置命令 |
| `set_message_bus()` | 设置消息总线 |
| `set_manager()` | 设置模块管理器 |
| `set_bot()` | 设置 bot 实例 |

## 三、命令详解

### 3.1 会话管理命令

**/new - 开始新会话**

- 功能：清除 iflow 的当前上下文，创建新的空白会话
- 使用方法：发送 `/new`
- 返回结果：
  - 成功：`✅ 已开始新会话，下次命令将从空白上下文开始`
  - 失败：`❌ 创建新会话失败: <错误信息>`
  - 无模块：`❌ 没有可用的 iflow 模块`

**/sessions - 查看历史会话**

- 功能：列出 iflow 的历史会话，显示会话 ID 和创建时间，最多显示最近 10 个会话
- 使用方法：发送 `/sessions`
- 返回结果：会话列表，包含会话 ID 和创建时间

### 3.2 状态查询命令

**/status - 查看服务状态**

- 功能：查看所有模块的运行状态、健康状态、性能指标、详细信息
- 使用方法：发送 `/status`
- 返回结果：各模块的状态信息汇总

**/history [模块ID] - 查看模块状态历史**

- 功能：查看模块的状态转换历史，显示状态转换的时间、原因和详细信息
- 使用方法：
  - `/history` - 查看所有模块的状态历史
  - `/history iflow_bot1` - 查看指定模块的状态历史

**/metrics [模块ID] - 查看模块性能指标**

- 功能：查看模块的性能指标，显示启动耗时、处理消息数、处理时间等
- 使用方法：
  - `/metrics` - 查看所有模块的性能指标
  - `/metrics iflow_bot1` - 查看指定模块的性能指标

### 3.3 tmux 管理命令

**/tmux list - 列出所有 tmux 会话**

- 功能：列出所有正在运行的 tmux 会话，显示会话名称、窗口数量、创建时间等信息
- 使用方法：`/tmux list` 或简写 `/tmux`
- 返回结果：tmux 会话列表

**/tmux create <name> - 创建新的 tmux 会话**

- 功能：创建新的 tmux 会话，检查会话是否已存在
- 使用方法：`/tmux create <会话名>`
- 返回结果：创建成功或失败信息

**/tmux kill <name> - 杀死指定的 tmux 会话**

- 功能：杀死指定的 tmux 会话，检查会话是否存在
- 使用方法：`/tmux kill <会话名>`
- 返回结果：删除成功或失败信息

**/tmux help - 显示帮助信息**

- 功能：显示 tmux 管理命令的帮助信息，提供使用示例和注意事项
- 使用方法：`/tmux help`

### 3.4 渠道管理命令

**/channel list - 列出所有渠道**

- 功能：列出所有配置的渠道，显示渠道类型和启用状态
- 使用方法：`/channel list`

**/channel status [channel_name] - 查看渠道状态**

- 功能：查看指定渠道或所有渠道的模块状态
- 使用方法：
  - `/channel status` - 查看所有渠道状态
  - `/channel status bot1` - 查看指定渠道状态

**/channel start <channel_name> - 启动渠道**

- 功能：启动指定渠道的所有模块
- 使用方法：`/channel start <渠道名>`

**/channel stop <channel_name> - 停止渠道**

- 功能：停止指定渠道的所有模块
- 使用方法：`/channel stop <渠道名>`

**/channel restart <channel_name> - 重启渠道**

- 功能：重启指定渠道的所有模块
- 使用方法：`/channel restart <渠道名>`

**/snapshot [channel_name] - 查看 tmux 界面快照**

- 功能：捕获并返回 tmux 会话的当前界面内容，让用户查看 iflow 的实际状态
- 使用方法：
  - `/snapshot` - 查看当前渠道的 tmux 界面
  - `/snapshot bot1` - 查看指定渠道的 tmux 界面

### 3.5 帮助命令

**/help - 显示帮助信息**

- 功能：显示系统概述和所有可用命令，提供命令使用提示
- 使用方法：`/help`

**/lscmd - 列出所有可用命令**

- 功能：列出所有可用命令及其说明，分类显示命令
- 使用方法：`/lscmd`

### 3.6 回复模式切换命令

**/scope - 回复模式切换**

| 用法 | 说明 |
|------|------|
| `/scope` | 查看当前模式 |
| `/scope reply_only` | 切换到仅回复模式 |
| `/scope all_messages` | 切换到全部消息模式 |
| `/scope reply` | 简写，等同于 reply_only |
| `/scope all` | 简写，等同于 all_messages |
| `/mode` | 等同于 `/scope` |

**模式映射：**

| 输入 | 映射结果 |
|------|----------|
| `reply`、`only`、`reply_only` | `reply_only` |
| `all`、`all_messages` | `all_messages` |

## 四、命令解析和执行流程

### 4.1 命令解析规则

| 规则 | 说明 |
|------|------|
| 以 `/` 开头 | 消息为命令 |
| 命令名不区分大小写 | 自动转换为小写 |
| 命令和参数分隔 | 使用空格分隔 |
| 参数可以为空 | 命令名后面没有内容 |

**解析结果格式：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `is_command` | boolean | 是否为命令 |
| `cmd_type` | string | "command" 或 "message" |
| `cmd_name` | string | 命令名（不含 /） |
| `cmd_args` | string | 命令参数 |
| `raw_content` | string | 原始消息内容 |

**示例：**

| 输入 | 命令名 | 参数 |
|------|--------|------|
| `/new` | new | 空 |
| `/status` | status | 空 |
| `/history iflow_bot1` | history | iflow_bot1 |
| `/channel start bot1` | channel | start bot1 |
| `你好` | 非命令 | 普通消息 |

### 4.2 命令执行流程

| 步骤 | 操作 |
|------|------|
| 1 | 检查是否为命令（`is_command`） |
| 2 | 检查命令是否已注册 |
| 3 | 执行命令处理函数 |
| 4 | 捕获异常并返回错误信息 |
| 5 | 未知命令返回 `None`（透传给 iflow） |

### 4.3 命令注册机制

| 项目 | 说明 |
|------|------|
| 存储方式 | 字典（命令名 → 处理函数） |
| 函数签名 | `async def handler(args: str, chat_id: str) -> str` |
| 初始化 | 初始化时自动注册所有内置命令 |

## 五、命令透传机制

### 5.1 透传场景

**未知的斜杠命令：**
- 用户发送以 `/` 开头但未注册的命令
- 例如：`/run`、`/config`、`/exit`、`/clear` 等
- 这些命令是 iflow 的原生命令

### 5.2 透传流程

```
用户发送命令
     │
     ▼
渠道模块接收
     │
     ▼
解析命令
     │
     ├─→ 已知命令 → 执行命令处理函数 → 返回结果 → 发送回复给用户 → 结束
     │
     └─→ 未知命令 → 创建消息对象 → 发送到消息总线 → 路由到 iflow 模块 → iflow 处理 → 返回结果
```

### 5.3 透传优势

| 优势 | 说明 |
|------|------|
| 保留 iflow 原生命令 | 用户可以直接使用 iflow 的所有命令 |
| 避免命令冲突 | 命令系统只处理特定于系统的命令 |
| 避免重复发送 | 已知命令执行后直接返回，不再发送到消息总线 |
| 易于维护 | 命令系统和 iflow 命令解耦 |

## 六、命令扩展机制

### 6.1 添加新命令

在 `_register_builtin_commands()` 方法中添加新的命令映射。

### 6.2 命令处理函数规范

| 项目 | 说明 |
|------|------|
| 函数签名 | `async def handler(args: str, chat_id: str) -> str` |
| 参数 args | 命令参数（命令名后面的部分） |
| 参数 chat_id | 聊天 ID（用于区分不同的会话） |
| 返回值 | 命令执行结果（Markdown 格式的字符串） |

**返回格式要求：**
- 返回 Markdown 格式的字符串
- 使用表情符号增强可读性
- 使用加粗、列表等格式化
- 使用换行符分隔不同部分

## 七、消息回复模式切换

### 7.1 需求概述

**当前行为：**
- 默认模式：只回复 ✦ 标记的消息（最终版本）
- 其他消息：不回复，包括 ✻ 标记的中间版本和其他消息类型

**新需求：**
- 切换模式：提供命令切换回复内容
- 模式1：只回复 ✦ 标记的消息（默认）
- 模式2：回复全部消息（包括 ✦、✻ 等）

### 7.2 核心概念

**回复模式（Reply Mode）**

| 属性 | 说明 |
|------|------|
| 定义 | 控制 IFlowModule 发送哪些类型的消息 |
| 位置 | IFlowModule 实例变量 |
| 持久化 | 存储在会话状态中 |

### 7.3 模式定义

| 模式 | 名称 | 描述 | 发送的消息 |
|------|------|------|-----------|
| `reply_only` | 仅回复模式 | 默认模式，只发送最终回复 | ✦ 标记的消息 |
| `all_messages` | 全部消息模式 | 发送所有类型的消息 | ✦、✻、及其他所有消息 |

### 7.4 实现逻辑

#### IFlowModule 修改

**新增状态变量：**
- `reply_mode: str = "reply_only"` - 默认为仅回复模式

**模式切换接口：**

| 方法 | 说明 |
|------|------|
| `set_reply_mode(mode: str)` | 设置回复模式 |
| `get_reply_mode()` | 获取当前回复模式 |
| `should_send_message(message)` | 判断是否应该发送消息 |

**消息发送规则：**

| 模式 | ✦ reply | ✻ other | 其他 |
|------|---------|---------|------|
| reply_only | ✓ 发送 | ✗ 不发送 | ✗ 不发送 |
| all_messages | ✓ 发送 | ✓ 发送 | ✓ 发送 |
