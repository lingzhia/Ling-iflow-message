# 消息总线设计

## 概述

MessageBus（消息总线）是 Ling-iflow 项目的核心组件，负责模块间消息路由和分发。采用**发布-订阅模式**实现模块解耦。

---

## 一、核心设计

### 1.1 核心理念

- **解耦**：模块间不直接依赖，通过消息总线通信
- **路由**：根据绑定关系自动路由消息
- **广播**：支持发布-订阅模式广播消息

### 1.2 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                       MessageBus                            │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │   modules   │  │  bindings   │  │ subscribers │         │
│  │  模块注册表  │  │  绑定关系   │  │  订阅者列表  │         │
│  └─────────────┘  └─────────────┘  └─────────────┘         │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                   核心方法                           │   │
│  │  register / bind / route / publish / subscribe      │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
        ↑                    ↑                    ↑
        │                    │                    │
   ┌────┴────┐         ┌────┴────┐         ┌────┴────┐
   │ WeChat  │         │ IFlow   │         │ Command │
   │ Module  │         │ Module  │         │ Handler │
   └─────────┘         └─────────┘         └─────────┘
```

## 二、核心数据结构

### 2.1 模块注册表

| 字段 | 类型 | 说明 |
|------|------|------|
| modules | Dict[str, BaseModule] | 模块ID到模块实例的映射 |

### 2.2 绑定关系

| 字段 | 类型 | 说明 |
|------|------|------|
| bindings | Dict[str, str] | 源模块ID到目标模块ID的映射 |

### 2.3 订阅者列表

| 字段 | 类型 | 说明 |
|------|------|------|
| subscribers | Dict[str, List[Callback]] | 主题到回调函数列表的映射 |

### 2.4 统计信息

| 字段 | 类型 | 说明 |
|------|------|------|
| messages_sent | int | 直接发送消息数 |
| messages_routed | int | 路由消息数 |
| messages_published | int | 广播消息数 |
| errors | int | 错误数 |

## 三、核心方法

### 3.1 模块管理

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `register_module(module)` | 注册模块 | bool |
| `unregister_module(module_id)` | 注销模块 | bool |
| `list_modules()` | 列出所有模块 | List[str] |

### 3.2 绑定管理

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `bind(from_module, to_module)` | 绑定两个模块 | bool |
| `unbind(from_module)` | 解绑模块 | bool |
| `get_binding(from_module)` | 获取绑定关系 | Optional[str] |
| `list_bindings()` | 列出所有绑定 | Dict[str, str] |

### 3.3 消息发送

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `send_to_module(message)` | 直接发送到指定模块 | bool |
| `route(message)` | 根据绑定关系路由，自动检查接收方可用性 | bool |
| `publish(topic, message)` | 广播到主题 | bool |
| `broadcast_to_bindings(message, sender_id)` | 无来源消息广播到所有绑定模块 | int |

### 3.4 订阅管理

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `subscribe(topic, callback)` | 订阅主题 | bool |
| `unsubscribe(topic, callback)` | 取消订阅 | bool |
| `list_topics()` | 列出所有主题 | Set[str] |

### 3.5 统计信息

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `get_stats()` | 获取统计信息 | Dict |
| `reset_stats()` | 重置统计信息 | None |

> **注意**：模块的启动/停止由 `ModuleManager` 控制，MessageBus 负责消息路由，并在路由时检查接收方可用性。

## 四、消息路由流程

### 4.1 点对点路由（带接收方检查）

```
消息到达 MessageBus.route()
        │
        ▼
检查 source_module 的绑定关系
        │
        ▼
bindings[source_module] → target_module_id
        │
        ▼
调用 ModuleManager 检查接收方可用性
        │
        ├─ 接收方不可用 → 生成错误响应消息 → 返回给发送方
        │
        └─ 接收方可用 → 发送消息到 target_module.receive()
```

**接收方检查内容**：
- 接收方模块是否存在
- 接收方模块是否正在运行
- 如果接收方是 iflow，还会检查是否处于"生成中"状态

### 4.2 无来源消息广播

```
消息到达 MessageBus.broadcast_to_bindings()
        │
        ▼
找出所有绑定了发送者的模块
        │
        ▼
跳过发送者本身，避免循环
        │
        ▼
向绑定的发起方广播消息
        │
        ▼
返回成功发送的模块数量
```

**使用场景**：当消息没有指定接收者时（如无来源消息），自动向所有相关渠道广播。

### 4.3 主题广播发布

```
消息到达 MessageBus.publish(topic)
        │
        ▼
获取主题的所有订阅者
        │
        ▼
并发调用所有订阅者回调
        │
        ▼
返回成功/失败统计
```

## 五、典型使用场景

### 5.1 场景1：微信 ↔ iflow 双向绑定

1. 创建消息总线
2. 创建并注册 wechat 模块和 iflow 模块
3. 设置双向绑定：wechat → iflow，iflow → wechat
4. 启动模块（由控制层管理）

### 5.2 场景2：多机器人配置

每个机器人独立配置，互不干扰：

- 机器人1：企业A的微信和对应的iflow
- 机器人2：企业B的微信和对应的iflow

每个机器人维护自己的绑定关系，各自独立运行。

### 5.3 场景3：命令处理器集成

1. 创建命令处理器并注册到消息总线
2. 微信消息先路由到命令处理器
3. 命令处理器判断是命令还是普通消息
4. 命令直接执行，普通消息转发到iflow

## 六、消息流转完整流程

```
企业微信消息到达
        │
        ▼
┌─────────────────┐
│  WeChatModule   │
│  receive()      │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   MessageBus    │
│   route()       │
└────────┬────────┘
         │
         ▼ (根据绑定)
┌─────────────────┐
│ CommandHandler  │ ← 检查是否为命令
│ parse_command() │
└────────┬────────┘
         │
    ┌────┴────┐
    │         │
    ▼         ▼
  命令      普通消息
    │         │
    ▼         ▼
┌───────┐ ┌─────────────┐
│执行命令│ │  IFlowModule│
│返回结果│ │  send()     │
└───────┘ └──────┬──────┘
                 │
                 ▼
         ┌─────────────┐
         │   iflow     │
         │   处理消息   │
         └──────┬──────┘
                 │
                 ▼
         ┌─────────────┐
         │ IFlowModule │
         │ subscribe   │
         └──────┬──────┘
                 │
                 ▼
         ┌─────────────────┐
         │   MessageBus    │
         │   route()       │
         └────────┬────────┘
                  │
                  ▼
         ┌─────────────────┐
         │  WeChatModule   │
         │  send_message() │
         └─────────────────┘
```

**命令路由优化：**
- 已知命令执行后直接返回，不发送到消息总线
- 未知命令透传给 iflow 处理
- 避免已知命令被重复发送到 iflow

## 七、设计原则

### 7.1 单一职责

- MessageBus 只负责消息路由和分发
- 不处理消息内容，不关心业务逻辑
- 模块职责独立，通过消息通信

### 7.2 依赖倒置

- 模块不直接依赖其他模块
- 模块通过 MessageBus 通信
- 绑定关系运行时配置

### 7.3 开闭原则

- 添加新模块无需修改 MessageBus
- 添加新绑定无需修改代码
- 扩展功能通过订阅机制

### 7.4 异步优先

- 所有消息处理使用 async/await
- 并发处理提高性能
- 非阻塞操作

## 八、错误处理

### 8.1 错误类型

| 错误 | 处理方式 |
|------|---------|
| 模块不存在 | 记录日志，返回 False |
| 绑定不存在 | 记录日志，返回 False |
| 消息发送失败 | 记录异常，更新错误计数 |
| 订阅者处理失败 | 记录异常，继续处理其他订阅者 |

### 8.2 容错机制

- 使用 return_exceptions 捕获所有异常
- 统计成功/失败数量
- 记录错误但不影响其他订阅者

## 九、性能考虑

### 9.1 并发处理

- 并发调用所有订阅者
- 使用 asyncio.gather 提高性能

### 9.2 内存管理

- 模块注册表：无上限，由使用方控制
- 绑定关系：无上限，由使用方控制
- 订阅者列表：无上限，由使用方控制

## 十、与其他组件关系

| 组件 | 关系 |
|------|------|
| ModuleManager | 控制层，负责模块生命周期管理和消息应答检查 |
| BaseModule | 模块基类，提供 receive() 方法 |
| Message | 统一消息格式 |
| WeChatModule | 注册到 MessageBus |
| IFlowModule | 注册到 MessageBus |
| CommandHandler | 注册到 MessageBus |

**说明**：
- ModuleManager 负责模块的创建、启动、停止、健康监控等控制逻辑
- MessageBus 持有 ModuleManager 引用，用于路由前检查接收方可用性
- 模块启动/停止由 ModuleManager 控制
- MessageBus 负责消息路由，并在路由时检查接收方状态
