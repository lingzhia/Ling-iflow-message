# 启动与部署方案

## 一、项目启动方案设计

### 1.1 当前启动流程分析

#### 现有实现

```
1. 创建 MessageBus
2. 创建并注册 IFlowModule
3. 创建并注册 WeChatModule
4. 设置绑定关系
5. 启动 IFlowModule
6. 启动 WeChatModule
```

#### 存在的问题

- ❌ 缺少健康检查机制
- ❌ 缺少依赖验证
- ❌ 启动失败处理不完善
- ❌ 没有优雅降级策略
- ❌ 启动状态可视化不足

### 1.2 完整启动方案

#### 1.2.1 模块依赖关系

```
MessageBus (核心，无依赖)
    ↓
IFlowModule (依赖 MessageBus)
    ↓
WeChatModule (依赖 MessageBus)
```

**依赖规则：**

- MessageBus 必须先启动（消息路由核心）
- IFlowModule 和 WeChatModule 可以并行启动（无相互依赖）
- 绑定关系在所有模块注册后设置

##### IFlowModule 健康检查

**检查项：**

```python
class IFlowModule:
    async def health_check(self) -> HealthStatus:
        """健康检查

        Returns:
            HealthStatus: 健康状态
        """
        checks = {
            "tmux_session": await self._check_tmux_session(),
            "iflow_process": await self._check_iflow_process(),
            "workspace": self._check_workspace(),
            "monitor": self._check_monitor()
        }

        overall_status = all(checks.values())

        return HealthStatus(
            healthy=overall_status,
            checks=checks,
            message="所有检查通过" if overall_status else "部分检查失败"
        )

    async def _check_tmux_session(self) -> bool:
        """检查 tmux 会话"""
        return await self.controller.check_tmux_session()

    async def _check_iflow_process(self) -> bool:
        """检查 iflow 进程"""
        return await self.controller.check_iflow_running()

    def _check_workspace(self) -> bool:
        """检查工作目录"""
        workspace = Path(self.workspace).expanduser()
        return workspace.exists() and workspace.is_dir()

    def _check_monitor(self) -> bool:
        """检查监控器"""
        return self.monitor is not None and self.monitor.running
```

#### 1.2.3 启动流程优化

##### 阶段 1: 预检查

```python
class LingIflowBot:
    async def _pre_check(self) -> bool:
        """启动前预检查

        Returns:
            是否通过预检查
        """
        logger.info("=" * 60)
        logger.info("启动前预检查")
        logger.info("=" * 60)

        # 1. 检查配置文件
        if not self._check_config():
            logger.error("❌ 配置文件检查失败")
            return False

        # 2. 检查系统依赖
        if not await self._check_dependencies():
            logger.error("❌ 系统依赖检查失败")
            return False

        # 3. 检查端口占用
        if not await self._check_ports():
            logger.error("❌ 端口检查失败")
            return False

        logger.info("✅ 预检查通过")
        return True

    def _check_config(self) -> bool:
        """检查配置文件"""
        required_sections = ["tmux_sessions", "bots"]

        for section in required_sections:
            if section not in self.config or not self.config[section]:
                logger.error(f"配置缺少必需的节: {section}")
                return False

        # 检查是否至少有一个启用的机器人
        enabled_bots = [bot for bot in self.config["bots"] if bot.get("enabled", False)]
        if not enabled_bots:
            logger.error("没有启用的机器人配置")
            return False

        logger.info("✅ 配置文件检查通过")
        return True

    async def _check_dependencies(self) -> bool:
        """检查系统依赖"""
        # 检查 tmux
        result = await asyncio.create_subprocess_shell(
            "which tmux",
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE
        )
        await result.wait()
        if result.returncode != 0:
            logger.error("❌ tmux 未安装")
            return False

        logger.info("✅ 系统依赖检查通过")
        return True

    async def _check_ports(self) -> bool:
        """检查端口占用"""
        used_ports = []

        for bot in self.config["bots"]:
            if not bot.get("enabled", False):
                continue

            port = bot.get("callback_port", 8788)
            if await self._is_port_in_use(port):
                used_ports.append(port)

        if used_ports:
            logger.error(f"❌ 端口已被占用: {used_ports}")
            return False

        logger.info("✅ 端口检查通过")
        return True

    async def _is_port_in_use(self, port: int) -> bool:
        """检查端口是否被占用"""
        try:
            _, writer = await asyncio.open_connection("127.0.0.1", port)
            writer.close()
            await writer.wait_closed()
            return True
        except:
            return False
```

##### 阶段 3: 启动模块（带重试）

```python
async def start(self) -> None:
    """启动所有模块（带重试机制）

    Args:
        max_retries: 最大重试次数（默认：3）
        retry_delay: 重试延迟（秒，默认：5）
    """
    logger.info("启动所有模块...")

    # 启动 IFlowModule（可并行）
    iflow_tasks = []
    for session_name, iflow in self.iflow_modules.items():
        task = self._start_module_with_retry(
            iflow,
            session_name,
            max_retries=3,
            retry_delay=5
        )
        iflow_tasks.append(task)

    iflow_results = await asyncio.gather(*iflow_tasks, return_exceptions=True)

    # 检查 IFlowModule 启动结果
    iflow_failed = []
    for i, result in enumerate(iflow_results):
        session_name = list(self.iflow_modules.keys())[i]
        if isinstance(result, Exception):
            logger.error(f"IFlowModule {session_name} 启动失败: {result}")
            iflow_failed.append(session_name)

    # 启动 WeChatModule（可并行）
    wechat_tasks = []
    for bot_name, wechat in self.wechat_modules.items():
        task = self._start_module_with_retry(
            wechat,
            bot_name,
            max_retries=3,
            retry_delay=5
        )
        wechat_tasks.append(task)

    wechat_results = await asyncio.gather(*wechat_tasks, return_exceptions=True)

    # 检查 WeChatModule 启动结果
    wechat_failed = []
    for i, result in enumerate(wechat_results):
        bot_name = list(self.wechat_modules.keys())[i]
        if isinstance(result, Exception):
            logger.error(f"WeChatModule {bot_name} 启动失败: {result}")
            wechat_failed.append(bot_name)

    # 启动状态总结
    logger.info("")
    logger.info("=" * 60)
    logger.info("启动状态总结")
    logger.info("=" * 60)
    logger.info(f"IFlowModule: {len(self.iflow_modules) - len(iflow_failed)}/{len(self.iflow_modules)} 成功")
    logger.info(f"WeChatModule: {len(self.wechat_modules) - len(wechat_failed)}/{len(self.wechat_modules)} 成功")

    if iflow_failed:
        logger.warning(f"IFlowModule 失败: {iflow_failed}")

    if wechat_failed:
        logger.warning(f"WeChatModule 失败: {wechat_failed}")

    # 检查是否可以正常运行
    if iflow_failed or wechat_failed:
        logger.warning("⚠️ 部分模块启动失败，功能可能受限")

    self._running = True
    logger.info("所有模块启动完成")

async def _start_module_with_retry(
    self,
    module,
    name: str,
    max_retries: int = 3,
    retry_delay: int = 5
) -> None:
    """带重试的模块启动

    Args:
        module: 模块实例
        name: 模块名称
        max_retries: 最大重试次数
        retry_delay: 重试延迟（秒）
    """
    for attempt in range(max_retries):
        try:
            logger.info(f"启动 {name} (尝试 {attempt + 1}/{max_retries})...")
            await module.start()
            logger.info(f"✅ {name} 启动成功")
            return
        except Exception as e:
            logger.warning(f"⚠️ {name} 启动失败 (尝试 {attempt + 1}/{max_retries}): {e}")

            if attempt < max_retries - 1:
                logger.info(f"等待 {retry_delay} 秒后重试...")
                await asyncio.sleep(retry_delay)
            else:
                raise
```

#### 1.2.4 优雅降级策略

##### 降级场景

| 场景 | 降级策略 | 说明 |
|------|---------|------|
| IFlowModule 启动失败 | 仅启动 WeChatModule，回复固定消息 | WeChat 可以接收消息但无法处理 |
| WeChatModule 启动失败 | 仅启动 IFlowModule | 可以通过 tmux 直接使用 iflow |
| 部分实例失败 | 跳过失败实例，启动其他实例 | 多实例部署时的高可用策略 |
| 端口占用 | 尝试使用备用端口 | 自动切换到备用端口 |

##### 实现方式

```python
class LingIflowBot:
    async def start_with_graceful_degradation(self) -> None:
        """带优雅降级的启动"""
        logger.info("启动所有模块（支持优雅降级）...")

        # 尝试启动所有模块
        try:
            await self.start()
        except Exception as e:
            logger.error(f"启动失败: {e}")

            # 检查是否有可用的模块
            if self._has_available_modules():
                logger.info("✅ 部分模块可用，以降级模式运行")
                self._running = True
            else:
                logger.error("❌ 所有模块启动失败")
                raise

    def _has_available_modules(self) -> bool:
        """检查是否有可用的模块"""
        # 至少有一个 IFlowModule 运行
        iflow_running = any(
            m.running for m in self.iflow_modules.values()
        )

        # 至少有一个 WeChatModule 运行
        wechat_running = any(
            m.running for m in self.wechat_modules.values()
        )

        return iflow_running or wechat_running
```

#### 1.2.7 启动命令

##### Python `-m` 参数说明

`-m` 是 Python 的模块运行参数，用于运行 Python 包中的模块。

**作用：**

- 添加当前目录到 Python 路径
- 启用相对导入
- 更好的包感知能力

**对比：**

| 命令 | 说明 | 推荐场景 |
|------|------|---------|
| `python3 -m src.bot` | 作为模块运行 | ✅ 推荐使用，兼容性好 |
| `python3 src/bot.py` | 直接运行脚本 | 适合简单场景 |
| `./src/bot.py` | 直接运行（需可执行权限） | 不推荐 |

**文件位置：**

- 主程序入口：`src/bot.py`
- 该文件存在且正常运行

**不是必须的**：可以直接使用 `python3 src/bot.py`，但推荐使用 `-m` 方式以获得更好的包兼容性。

##### 配置文件默认值

项目已设置默认配置文件为 `config.json`，**启动命令可以省略配置文件参数**。

**当前默认配置：**

**配置文件位置：**

- 默认：项目根目录下的 `config.json`
- 也可以指定其他路径，如：`config-dev.json`

##### 快速启动说明

**快速启动的定义：**

快速启动是指**跳过健康检查**，直接启动模块，适用于以下场景：

- 开发调试时快速启动
- 确认系统状态良好时
- CI/CD 自动化测试

**快速启动与完整启动对比：**

| 项目 | 完整启动 | 快速启动 |
|------|---------|---------|
| 预检查 | ✅ 执行 | ❌ 跳过 |
| 健康检查 | ✅ 执行 | ❌ 跳过 |
| 启动时间 | 较慢（10-20秒） | 较快（5-10秒） |
| 适用场景 | 生产环境 | 开发/测试 |
| 可靠性 | 高 | 中 |

## 二、IFlow 启动就绪检查方案

### 2.1 问题背景

在测试过程中发现，`IFlowController.check_iflow_running()` 方法在 iflow 启动后立即返回 `True`，但实际上 iflow 仍处于"生成中"状态，无法接受消息。

**测试结果：**

```
时间  iflow状态  监控器状态  检测情况
1s   running=True  idle        版本号已显示 ⚠️ 检测到：生成中
2s   running=True  idle        版本号已显示 ⚠️ 检测到：生成中
3s   running=True  idle        版本号已显示 ⚠️ 检测到：生成中
4s   running=True  idle        ✅ UI 已就绪 ⚠️ 检测到：生成中
...
20s  running=True  idle        ✅ UI 已就绪 ⚠️ 检测到：生成中
```

**关键问题：**

- ✅ UI 界面已显示（输入框、欢迎消息、版本号）
- ❌ iflow 一直显示 "生成中" 进度条，持续 20 秒
- ❌ `check_iflow_running()` 只检查 UI，没有检查"生成中"状态
- ❌ 工具在 iflow 未就绪时发送消息，导致消息丢失

### 2.2 解决方案

#### 2.2.1 添加 `check_iflow_ready()` 方法

```python
async def check_iflow_ready(self) -> bool:
    """检查 iflow 是否真正准备好接受消息

    检查条件：
    1. tmux 会话存在
    2. UI 已就绪（检测到输入框、欢迎消息、版本号）
    3. 不在"生成中"状态（没有进度条）
    4. 输入框可用

    Returns:
        iflow 是否就绪
    """
    # 1. 检查 tmux 会话
    if not await self.check_tmux_session():
        return False

    # 2. 捕获输出
    output = await self.capture_output(lines=100)
    if not output:
        return False

    # 3. 检查 UI 是否就绪
    iflow_indicators = [
        "输入消息或@文件路径",
        "Hi～今天想做点什么",
        "版本号:",
    ]

    ui_ready = any(indicator in output for indicator in iflow_indicators)
    if not ui_ready:
        return False

    # 4. 检查是否在"生成中"（关键检查）
    if "生成中" in output or "⠏" in output or "⠙" in output:
        return False  # ❌ 还在生成中

    # 5. 检查输入框是否可用
    if ">   输入消息或@文件路径" not in output:
        return False  # ❌ 输入框未就绪

    # 6. 所有条件满足，认为就绪
    return True
```

```python
async def wait_for_ready(self, timeout: float = 60.0) -> bool:
    """等待 iflow 完全就绪

    Args:
        timeout: 超时时间（秒）

    Returns:
        是否就绪
    """
    logger.info(f"[{self.module_id}] 等待 iflow 就绪...")

    start_time = time.time()
    while time.time() - start_time < timeout:
        if await self.controller.check_iflow_ready():
            logger.info(f"[{self.module_id}] iflow 已就绪")
            return True
        await asyncio.sleep(1)

    logger.warning(f"[{self.module_id}] 等待 iflow 就绪超时 ({timeout}秒)")
    return False

@property
def is_ready(self) -> bool:
    """检查 iflow 是否就绪（同步版本，用于快速检查）"""
    return self._is_ready
```

### 3.4 实现方式

使用 typer 框架构建 CLI：

```python
#!/usr/bin/env python3
"""Ling-iflow 项目管理脚本"""

import typer
import subprocess
from pathlib import Path

app = typer.Typer()

@app.command()
def start(
    config: str = typer.Option("config.json", "--config", "-c", help="配置文件路径"),
    daemon: bool = typer.Option(False, "--daemon", "-d", help="后台运行")
):
    """启动服务"""
    cmd = ["python3", "-m", "src.bot", config]
    if daemon:
        cmd = ["nohup"] + cmd + [">", "logs/bot.log", "2>&1", "&"]
    subprocess.run(" ".join(cmd), shell=True)

@app.command()
def stop():
    """停止服务"""
    subprocess.run("pkill -f 'src.bot'", shell=True)

@app.command()
def restart():
    """重启服务"""
    subprocess.run("pkill -f 'src.bot'", shell=True)
    subprocess.run("python3 -m src.bot", shell=True)

@app.command()
def status():
    """查看服务状态"""
    result = subprocess.run("ps aux | grep 'src.bot' | grep -v grep", shell=True)
    if result.returncode == 0:
        print("✅ 服务运行中")
    else:
        print("❌ 服务未运行")

@app.command()
def logs(
    follow: bool = typer.Option(False, "--follow", "-f", help="持续跟踪日志")
):
    """查看服务日志"""
    if follow:
        subprocess.run("tail -f logs/bot.log", shell=True)
    else:
        subprocess.run("tail -100 logs/bot.log", shell=True)

if __name__ == "__main__":
    app()
```

## 五、渠道配置简化方案（2026-03-18）

### 5.1 方案背景

在实施过程中发现，原有的 `enabled` 字段设计存在以下问题：

1. **配置复杂**：需要手动设置 `enabled` 字段来控制渠道是否可用
2. **灵活性不足**：无法启动未启用的渠道，导致测试困难
3. **状态混乱**：配置文件中同时包含配置信息和运行状态
4. **用户困惑**：用户不理解为什么配置了渠道却无法启动

### 5.2 简化方案设计

#### 核心原则

1. **去除 enabled 字段**：配置文件只包含配置信息，不包含运行状态
2. **第一个渠道默认**：不指定渠道时，使用配置文件中的第一个渠道
3. **明确指定优先**：指定渠道时，启动指定的渠道
4. **配置纯粹化**：配置文件变成纯粹的"信息库"

#### 配置文件结构

**修改前：**
```json
{
  "bots": [
    {
      "name": "bot1",
      "enabled": true,
      "corp_id": "...",
      "agent_id": "1000002",
      ...
    },
    {
      "name": "bot2",
      "enabled": true,
      ...
    }
  ],
  "simulator_channels": [
    {
      "name": "simulator1",
      "enabled": false,
      "host": "localhost",
      "port": 19999
    }
  ]
}
```

**修改后：**
```json
{
  "bots": [
    {
      "name": "bot1",
      "corp_id": "...",
      "agent_id": "1000002",
      ...
    },
    {
      "name": "bot2",
      ...
    }
  ],
  "simulator_channels": [
    {
      "name": "simulator1",
      "host": "localhost",
      "port": 19999
    }
  ]
}
```

**关键变化：**
- 移除所有 `enabled` 字段
- 配置更简洁
- 所有渠道都可以被使用

### 5.3 行为定义

#### 不指定渠道时

```bash
./manage.py start
```

**行为：**
- 启动配置文件中的**第一个渠道**
- 按照配置文件中的顺序：先 `bots`，后 `simulator_channels`
- 第一个渠道通常是 `bot1`

#### 指定渠道时

```bash
./manage.py start --channel simulator1
```

**行为：**
- 启动指定的渠道
- 渠道必须在配置文件中存在
- 无论渠道在配置文件中的位置如何，都可以被启动

#### 查看可用渠道

