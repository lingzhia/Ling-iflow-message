# 通用组件设计

## 概述

通用组件是指可被多个渠道复用的组件。本文档介绍 MessageConverter 和 NotificationManager 两个通用组件的设计。

**注意**：MessageConverter 可被所有渠道复用。NotificationManager 可被 WeChatChannel 和 FeishuChannel 复用，SimulatorChannel 不使用。

---

## 一、MessageConverter（消息转换器）

### 1.1 职责

- 将平台原始消息转换为标准 Message 格式
- 将标准 Message 格式转换为平台消息格式
- 提供统一的消息转换接口

### 1.2 主要方法

| 方法 | 说明 |
|------|------|
| `from_platform_message()` | 从平台消息创建标准 Message |
| `to_platform_message()` | 从标准 Message 创建平台消息 |
| `create_wechat_inbound_message()` | 创建企业微信入站消息 |
| `create_wechat_outbound_message()` | 创建企业微信出站消息 |
| `create_iflow_inbound_message()` | 创建 iflow 入站消息 |
| `create_iflow_outbound_message()` | 创建 iflow 出站消息 |
| `register_inbound_converter()` | 注册自定义入站转换器 |
| `register_outbound_converter()` | 注册自定义出站转换器 |

### 1.3 设计要点

- 支持多种平台消息格式
- 提供默认值和容错处理
- 支持自定义转换规则
- 可以扩展支持新平台

### 1.4 消息转换流程

```
平台原始消息
    ↓
解析平台消息格式
    ↓
提取内容、元数据
    ↓
创建标准 Message 对象
    ↓
返回 Message
```

### 1.5 实现位置

- **文件**：`src/modules/common/converter.py`

## 二、NotificationManager（通知管理器）

### 2.1 职责

- 发送启动通知
- 发送停止通知
- 管理通知模板
- 支持自定义通知处理器

### 2.2 主要方法

| 方法 | 说明 |
|------|------|
| `send_startup_notification()` | 发送启动通知 |
| `send_shutdown_notification()` | 发送停止通知 |
| `render_template()` | 渲染通知模板 |
| `register_template()` | 注册自定义模板 |
| `get_template()` | 获取模板内容 |
| `register_notification_handler()` | 注册通知处理器 |
| `unregister_notification_handler()` | 注销通知处理器 |
| `send_custom_notification()` | 发送自定义通知 |

### 2.3 设计要点

- 支持模板系统
- 支持自定义通知内容
- 支持动态注册通知处理器
- 提供模板和处理器管理接口

### 2.4 模板系统

NotificationManager 使用预定义的模板来格式化通知消息：

| 模板名称 | 用途 | 格式 |
|----------|------|------|
| startup | 启动通知 | 包含服务名称、启动时间 |
| startup_with_error | 异常启动通知 | 包含错误信息和可用命令 |
| shutdown | 停止通知 | 包含服务名称、停止时间、重启命令 |

### 2.5 实现位置

- **文件**：`src/modules/common/notifications.py`

## 三、架构位置

### 3.1 组件关系图

```
┌─────────────────────────────────────────────────────────┐
│                    渠道模块                             │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐      │

│                          │                               │
│                          ▼                               │
│              ┌───────────────────┐                       │
│              │  MessageConverter  │                      │
│              └───────────────────┘                       │
│                          │                               │

│              └───────────────────┘                       │
└─────────────────────────────────────────────────────────┘
```

### 3.2 数据流

1. **接收消息时**：
   - 渠道模块接收平台消息
   - MessageConverter 转换为标准格式
   - 发送到 MessageBus

2. **发送消息时**：
   - IFlowModule 生成消息
   - NotificationManager 添加通知
   - MessageBus 路由到目标渠道
   - 渠道模块发送平台消息

## 四、使用示例

### 4.1 MessageConverter 使用

```python
from src.modules.common.converter import MessageConverter

converter = MessageConverter()

# 从平台消息创建标准 Message
platform_message = {...}  # 企业微信/飞书消息格式
message = converter.from_platform_message(platform_message)

# 从标准 Message 创建平台消息
platform_output = converter.to_platform_message(message)
```

### 4.2 NotificationManager 使用

```python
from src.modules.common.notifications import NotificationManager

notification = NotificationManager()

# 注册通知处理器
notification.register_notification_handler("startup", my_handler)

# 发送启动通知
await notification.send_startup_notification(
    module_name="iFlow",
    service_info="...",
    quick_start="...",
    tips="..."
)
```

## 六、扩展指南

### 6.1 添加新的消息转换器

1. 使用 `register_inbound_converter()` 注册自定义入站转换器
2. 使用 `register_outbound_converter()` 注册自定义出站转换器
3. 在转换器中实现平台特定的消息格式解析

### 6.2 添加新的通知模板

1. 使用 `register_template()` 注册新模板
2. 调用 `render_template()` 渲染模板
3. 使用 `send_custom_notification()` 发送通知

### 6.3 支持新的通知渠道

1. 注册通知处理器 `register_notification_handler()`
2. 在处理器中实现发送到特定渠道的逻辑

## 七、总结

### 7.1 核心价值

| 价值 | 说明 |
|------|------|
| 代码复用 | 通用功能集中管理，避免重复代码 |
| 易于扩展 | 新增渠道只需实现平台交互 |
| 便于测试 | 组件独立，易于单元测试 |
| 维护简单 | 修改一处即可影响所有渠道 |

### 7.2 设计原则

- **单一职责**：每个组件职责单一
- **开闭原则**：对扩展开放，对修改关闭
- **依赖倒置**：通过接口抽象，不依赖具体实现
