# 模拟器渠道设计

## 一、概述

SimulatorChannel（模拟器渠道）是 Ling-iflow 项目提供的通用消息测试渠道，通过 Socket 通信接收测试工具的消息，用于测试 iflow 模块的核心功能，不依赖具体的企业微信或其他社交渠道。

---

## 二、职责

### 2.1 核心职责

- 通过 Socket 接收测试工具的消息
- 发送消息到 MessageBus
- 支持 JSON 格式消息
- 支持多客户端连接

### 2.2 设计目标

**核心概念**：

**MessageSimulator（消息模拟器）**
- 作为项目的一个渠道模块
- 通用性强，不模拟任何特定渠道
- 通过 Socket 接收测试工具的消息
- 通过 Socket 发送 iflow 的回复给测试工具

**TestClientTool（测试客户端工具）**
- 独立的可执行程序
- 模拟用户发送消息，接收并显示 iflow 的回复
- 支持交互模式和命令行模式
- 完全独立于项目运行

## 三、架构设计

### 3.1 目录结构

```
src/modules/channel/
├── __init__.py
├── wechat.py      # WeChatChannel
├── feishu.py      # FeishuChannel
└── simulator.py   # SimulatorChannel

tools/
└── test_client.py # 测试客户端工具
```

### 3.2 整体架构

```
TestClientTool (客户端)
        ↓
   TCP 连接
        ↓
SimulatorChannel (服务端)
        ↓
    MessageBus
        ↓
   IFlowModule
```

### 3.3 组件关系

| 组件 | 位置 | 类型 | 角色 | 功能 |
|------|------|------|------|------|
| SimulatorChannel | `src/modules/channel/simulator.py` | 渠道 | TCP 服务端 | 接收测试工具消息，发送 iflow 回复 |
| TestClientTool | `tools/test_client.py` | 独立程序 | TCP 客户端 | 模拟用户交互，发送消息，显示回复 |
| Socket 通信 | - | 协议 | - | TCP、JSON + 长度前缀、长连接 |

## 四、Socket 通信协议

### 4.1 消息格式

使用 JSON 格式封装消息，易于扩展和调试。

**消息结构：**
| 部分 | 说明 |
|------|------|
| 消息头 | 包含消息类型、消息 ID、时间戳 |
| 消息体 | 包含具体的数据内容 |

### 4.2 消息类型

**1. 客户端 → 服务端**

| 类型 | 说明 | 方向 |
|------|------|------|
| user_message | 用户发送的消息 | 客户端 → 服务端 |
| heartbeat | 心跳消息 | 客户端 → 服务端 |
| close | 关闭连接消息 | 客户端 → 服务端 |

**2. 服务端 → 客户端**

| 类型 | 说明 | 方向 |
|------|------|------|
| reply_message | iflow 回复消息 | 服务端 → 客户端 |
| bot_message | 命令回复消息 | 服务端 → 客户端 |

### 4.3 传输机制

**消息封装流程：**
1. 将消息序列化为 JSON 字符串
2. 计算消息字节数（使用 UTF-8 编码）
3. 将字节数转换为 4 字节的长度字段（网络字节序）
4. 将长度字段和消息内容组合

**接收流程：**
1. 读取 4 字节的长度字段
2. 将长度字段转换为整数
3. 根据长度读取完整消息
4. 解析 JSON 消息
5. 验证消息格式

### 4.4 网络配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 地址 | localhost | 监听地址 |
| 端口 | 19999 | 监听端口 |

## 五、SimulatorChannel 详细设计

### 5.1 核心职责

1. 监听 TCP 端口，接受客户端连接
2. 管理多个客户端连接（可选）
3. 接收客户端发送的消息
4. 将消息转换为标准格式，发送到 MessageBus
5. 接收 MessageBus 返回的回复
6. 将回复通过 TCP 发送给对应的客户端
7. 处理连接的建立、维护和关闭

### 5.2 模块组成

| 模块 | 职责 |
|------|------|
| Socket 服务端 | 监听指定端口，接受新连接 |
| 连接处理器 | 处理单个客户端的所有消息 |
| 消息转换 | 复用 MessageConverter 进行格式转换 |
| 连接管理器 | 维护活跃连接列表，处理连接建立和断开 |

### 5.3 工作流程

**启动流程：**
1. 创建 TCP socket
2. 绑定到指定端口
3. 开始监听
4. 启动接受连接的后台任务

**接收消息流程：**
1. 从 socket 读取数据
2. 读取 4 字节的消息长度
3. 根据长度读取完整消息
4. 解析 JSON 消息
5. 验证消息格式
6. 转换为 MessageBus 消息
7. 发送到 MessageBus

**发送回复流程：**
1. 从 MessageBus 接收回复
2. 转换为 Socket 消息格式
3. 序列化为 JSON
4. 计算消息长度
5. 写入长度字段（4 字节）
6. 写入消息内容

**关闭流程：**
1. 停止接受新连接
2. 关闭所有活跃连接
3. 通知所有客户端
4. 关闭服务端 socket
5. 清理资源

### 5.4 状态管理

**服务端状态：**
| 状态 | 说明 |
|------|------|
| 未启动 | 初始状态 |
| 监听中 | 正在监听端口 |
| 已停止 | 已关闭 |

**统计信息：**
| 类型 | 说明 |
|------|------|
| 活跃连接数 | 当前连接的客户端数量 |
| 发送消息数 | 已发送的消息数量 |
| 接收消息数 | 已接收的消息数量 |
| 错误消息数 | 处理失败的消息数量 |

### 5.5 错误处理

| 错误类型 | 处理方式 |
|----------|---------|
| 连接错误 | 记录日志，关闭异常连接 |
| 消息解析错误 | 记录日志，断开连接 |
| 发送失败 | 记录日志 |

## 六、TestClientTool 详细设计

### 6.1 核心职责

1. 连接到 MessageSimulator 服务端
2. 提供交互式用户界面
3. 接收用户输入，转换为消息发送
4. 接收服务端回复，显示给用户
5. 管理连接状态
6. 提供命令行操作接口

### 6.2 运行模式

**1. 交互模式**

- 连接到服务器后等待用户输入
- 用户输入消息后按回车发送
- 工具等待回复，显示结果

**2. 命令行模式**

| 选项 | 说明 |
|------|------|
| `--mode interactive` | 交互模式 |
| `--send <message>` | 发送消息后退出 |
| 位置参数 host | 服务端地址（默认：localhost） |
| 位置参数 port | 服务端端口（默认：19999） |

### 6.3 支持命令

交互模式支持的命令：

| 命令 | 说明 |
|------|------|
| `/help` | 显示帮助信息 |
| `/status` | 显示连接状态 |
| `/stats` | 显示消息统计 |
| `/quit` 或 `/exit` | 退出工具 |

## 九、优势总结

| 优势 | 说明 |
|------|------|
| 通用性强 | 不依赖具体渠道，可以测试任何渠道以外的功能 |
| 独立性高 | 测试工具完全独立，不依赖项目运行环境 |
| 易于实现 | Socket 通信成熟可靠，不需要复杂的依赖 |
| 可扩展性好 | 支持添加新功能，可以升级通信机制 |
| 改动最小 | 只需添加 SimulatorChannel，复用 MessageConverter |
| 架构统一 | 与 WeChatModule 使用相同的架构模式 |

## 十、风险和应对

| 风险 | 应对措施 |
|------|----------|
| 端口冲突 | 支持端口配置，端口冲突检测，自动选择可用端口 |
| 网络不稳定 | 心跳机制，自动重连，超时处理 |
| 消息格式兼容性 | 版本协商，向后兼容，格式验证 |
| 并发连接管理 | 连接池管理，资源限制，优雅降级 |

## 十二、总结

### 12.1 架构一致性

| 对比项 | MockWeChatModule | SimulatorModule |
|--------|------------------|-----------------|
| 用途 | 集成测试 | 功能测试 |
| 特性 | 模拟企业微信 | 通用模拟器 |
| 架构 | 模拟特定渠道 | 不模拟任何特定渠道 |

**架构一致性：**
- WeChatModule = WeChatChannel + 通用组件
- SimulatorModule = SimulatorChannel + 通用组件
- 都复用 MessageConverter

### 12.2 与 MessageBus 的关系

- MessageSimulator 作为普通模块注册
- 使用标准的消息路由机制
- 不修改 MessageBus
